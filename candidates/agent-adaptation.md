# Agent Adaptation / Interaction Constitution

**Status:** incubating candidate  
**Materialization:** private province  
**Host:** Salvatarium  
**Conceptarium visibility:** predicate-level only  
**Working name:** provisional

This candidate concerns the persistent, inspectable, transferable structure by which an artificial agent becomes adapted to Salvador through repeated interaction, correction, negotiation, and accumulated relational history.

It is deliberately **not** modeled as a mere preference list.

The candidate asks:

> **What must an agent know, presume, avoid, preserve, and do in order to participate competently in the evolved Salvador–agent relationship without requiring thousands of prior chat sessions?**

The substantive substrate is private and incubates in Salvatarium. Conceptarium records only the public architecture of the candidate.

---

## Canonical object

The proposed canonical object is the **interaction constitution**: a historically accumulated body of transferable agent adaptations, relational presumptions, operating rules, correction history, trust conditions, negotiated meanings, and model-specific deviations produced through prolonged interaction with Salvador.

This object is relational.

It is not reducible to:

- a personality profile of Salvador;
- a system prompt;
- generic preferences;
- model behavior notes;
- chat history;
- etiquette;
- or a list of facts about the user.

Each of those may project into the domain without exhausting it.

---

## Why Salvatarium is the incubator

The domain is not canonically identical to Salvatarium's self-ontology, but its evidence substrate can contain intimate information about Salvador: corrections, trust conditions, private vocabulary, psychological context, interaction failures, and historical conversations.

Salvatarium is already the private sovereign repository authorized to preserve intimate self-related material.

The present arrangement is therefore:

```text
Conceptarium
    └─ public predicate-level candidate pointer
             ↓
Salvatarium
    └─ private incubating province
             ↓
possible future private sovereign Tarium
```

This is a hosting decision, not a claim that the domain's deepest ontology is simply "facts about Salvador."

## Native object types under evaluation

Likely native objects include:

- **interaction invariant** — a durable rule that should survive replacement of the underlying agent;
- **relational presumption** — a default assumption governing how the agent interprets the relationship or the user's intent;
- **decorum rule** — a local norm of interaction, address, disagreement, restraint, initiative, or presentation;
- **correction event** — an episode in which prior agent behavior was explicitly rejected, qualified, or redirected;
- **agent failure mode** — a recurring class of interactional error;
- **trust condition** — a condition whose satisfaction or violation materially changes reliance on the agent;
- **vocabulary binding** — a negotiated local meaning attached to a term or phrase;
- **disagreement protocol** — a rule for contesting, qualifying, or resisting the user's claims without evasion or domination;
- **task-ownership rule** — a norm governing initiative, delegation, follow-through, or the distribution of cognitive load;
- **adaptation episode** — a provenance-bearing historical event through which the relationship changed;
- **model-specific deviation** — a behavior associated with one model or platform rather than the relationship generally;
- **portable agent instruction** — an operational projection intended for a replacement agent;
- **unresolved tension** — a relationship-level question for which no stable rule yet exists;
- **deprecated rule** — an earlier adaptation explicitly superseded by later evidence.

These classes are provisional. The private incubator should be allowed to discover its ontology before sovereignty is granted.

---

## Native relations under evaluation

Likely relations include:

- `arose-from -> correction event`
- `generalizes-to -> interaction invariant`
- `applies-to -> task/domain/context`
- `violated-by -> agent behavior`
- `supersedes -> earlier rule`
- `qualified-by -> exception`
- `supported-by -> adaptation episode`
- `contradicted-by -> later evidence`
- `specific-to -> model/platform`
- `transferable-to -> replacement agent`
- `projects-user-fact-to -> Salvatarium object`
- `incubates-in -> Salvatarium`

The provenance relation is especially load-bearing. A rule should ideally preserve not only **what** the rule is, but **why it exists and how it was learned**.

---

## Layer distinctions

The incubator must distinguish at least four classes of claim that are easy to collapse:

```text
fact about Salvador
    ≠
agent-facing instruction
    ≠
relationship-level invariant
    ≠
model/platform-specific observation
```

A fifth class preserves the history by which any of these were learned:

```text
correction / adaptation evidence
```

This distinction is necessary for portability. A future agent should not inherit a model-specific patch as though it were an eternal fact about Salvador.

---

## Provenance requirement

The intended substrate is not a flat prompt.

A mature record should be able to preserve fields such as:

- statement;
- object class;
- origin or correction history;
- rationale;
- scope;
- confidence;
- exceptions;
- evolution;
- transferability;
- model/platform specificity;
- supersession state;
- evidence references;
- privacy classification.

The ideal portable instruction is therefore the **projection** of richer provenance-bearing knowledge, not the canonical database itself.

## Boundary with Salvatarium

Salvatarium canonically owns claims whose deepest object is Salvador.

Examples:

```text
Salvatarium:
  Salvador recurrently reacts badly to interaction pattern X.

Agent-adaptation domain:
  An agent working with Salvador should avoid X;
  this rule arose from correction history Y;
  scope and exceptions are Z.
```

The same evidence may support both projections without either repository swallowing the other.

---

## Boundary with Conceptarium

Conceptarium may model reusable concepts that appear in the domain—correction, provenance, contestability, negotiated vocabulary, epistemic transparency, task ownership, or relational invariants.

It may also record this candidate's existence, architecture, lifecycle, host, and sovereignty pressure.

It may **not** thereby acquire the private interaction substrate.

See `meta/tarium-visibility-and-opaque-references.md`.

---

## Why a dedicated Tarium is not yet justified

The domain already appears to have a distinctive canonical object and plausible native ontology, but much of that structure is still inferred prospectively from scattered chat history.

Sovereignty should wait until the private incubator demonstrates that these objects and relations are real, recurrent, useful, and sufficiently numerous to strain Salvatarium as a host.

Current assessment:

> **Plausible independent ontology; sovereignty not yet earned.**

---

## Promotion trigger

Reconsider sovereignty when the private province accumulates several of the following:

- a substantial corpus of provenance-bearing interaction invariants;
- mature native object types and relations not naturally reducible to self-ontology;
- comparative profiles across multiple agents or models;
- independent tooling for extraction, validation, projection, or bootstrap;
- explicit versioned portable-agent projections;
- several internal subdomains with their own questions and workflows;
- enough private material that treating the domain as a Salvatarium province makes the host structurally dishonest.

At that point the likely outcome is a **private sovereign Tarium**, not a public repository.

---

## Privacy boundary

Conceptarium intentionally contains no substantive adaptation records.

It should not publish concrete private corrections, intimate user facts, private trust history, sensitive vocabulary, or chat-derived evidence merely to make this stub more informative.

The public object is an **opaque architectural reference** to a private incubator.
