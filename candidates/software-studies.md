# Software Studies — approved Tarium stub

- **Lifecycle:** approved

## Working name / aliases

Software Studies; Software Catalogue.

## Canonical object of study

Software as an object of descriptive, historical, taxonomic, and theoretical study.

## Core question

**What is software? What kinds exist? How did they emerge? How do their abstractions differ?**

## Native entity types

Programming language, paradigm, compiler, interpreter, operating system, database, GUI, distributed system, package manager, shell, build system, serialization format, protocol, runtime, library, framework.

## Native relations

Implements, compiles-to, interprets, depends-on, serializes, communicates-via, abstracts, executes-on, packages, links-to, supersedes.

## Major proposed subdomains

Languages; paradigms; operating systems; databases; interfaces; distributed systems; build/package ecosystems; protocols; software history; abstractions; generative/declarative systems.

## Likely overlaps with existing Tariums

Software Philosophy, Engineering, Designarium, Linguarium, Projectarium.

## Why projection into an existing repo is insufficient

Software Philosophy is normative—how Salvador's software ought to be built. Software Studies asks descriptive, historical, comparative, and theoretical questions about software as a field.

## Example artifacts

Language profiles; paradigm genealogies; OS/database histories; compiler architecture maps; software-category ontology; comparative abstraction studies; generative/declarative theory contributions.

## Phenomenological / confessional role

Programming experience, conceptual elegance, frustration, legibility, taste, and first-person interaction with software systems may be preserved separately from technical description.

Passed in principle.

## Promotion evidence

Distinct canonical objects, large native vocabulary, many major technical subdomains, extensive genealogy, independent descriptive question-set from Software Philosophy.
