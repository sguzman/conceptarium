# Tarium Sovereignty and Lifecycle

A Tarium repository is not created merely because a subject is interesting, emotionally salient, fashionable, or temporarily exciting.

The Tarium family uses a constitutional promotion process.

The governing distinction is:

> **Intensity admits a subject to consideration. It does not grant repository sovereignty.**

Conceptarium therefore preserves candidate domains before repository creation, allows them to incubate inside existing domains, records failed or merged candidates as knowledge, and promotes a candidate only when it demonstrates a sufficiently independent ontology.

---

# Why a sovereignty test exists

Without a promotion threshold, every attractive subject could become a repository.

That would destroy the meaning of the family.

A sovereign Tarium should represent a domain whose internal structure is substantial enough that forcing it into another repository would make the host ontology structurally dishonest.

The question is not:

> "Do I want to learn this?"

The question is:

> **"Does this domain possess enough native ontological structure, native questions, and durable material to deserve local sovereignty?"**

---

# The Tarium Sovereignty Test

A candidate is strong evidence for sovereignty when it possesses most of the following.

## 1. Distinctive canonical object of study

The domain has a recognizable primary substrate or family of substrates that it studies in its own right.

Examples:

- engineered artifacts;
- mathematical objects;
- buildings;
- economies;
- nonhuman organisms;
- software systems.

## 2. Native object types and relations

The domain generates entity types and relationships that are not merely borrowed from another Tarium.

A repository should be able to develop a meaningful local ontology rather than function only as a tag or view over another ontology.

## 3. Native questions

The domain asks questions that are not merely another repository's perspective on the same object.

For example:

- Engineering asks **how does this thing actually work?**
- Design asks **why was it made this way, and is this a good way for a human artifact to be?**

Those questions may concern the same object while remaining ontologically independent.

## 4. Multiple substantial subdomains

The candidate should contain enough internal differentiation to support several major provinces, research programs, object families, or methods.

A subject with only one narrow object class is usually better represented as a module.

## 5. Objective and theoretical depth

The domain should support both:

- externally auditable factual material; and
- analysis, explanation, theory, argument, or model-building.

A candidate that can only accumulate lists is usually not sovereign yet.

## 6. Genealogies and instantiated cases

The domain should support meaningful histories, genealogies, comparisons, case studies, biographies, exemplars, failures, or instantiated profiles.

## 7. Phenomenological or evaluative projection where relevant

The domain should leave room for first-person interpretation, taste, confession, aesthetic response, bodily experience, moral judgment, or other phenomenology without confusing that layer with objective truth.

Not every domain needs equal phenomenological density, but the Tarium Repository Schema must remain available.

## 8. Structural pressure against the host

The decisive criterion is often architectural:

> **Would continued projection into an existing Tarium make that host repository structurally dishonest?**

If the candidate repeatedly demands its own object types, relations, methods, provenance rules, major subdomains, and analytical machinery, sovereignty becomes justified.

---

# What does not establish sovereignty

None of the following is sufficient by itself:

- intense interest;
- ignorance of a subject;
- emotional excitement;
- a pleasing repository name;
- one large project;
- one useful dataset;
- one perspective on an object already canonically owned elsewhere;
- the fact that a domain could hypothetically support an ontology.

These are reasons to create or enrich a **candidate stub**, not reasons to instantiate a sovereign repository.

---

# Two independent axes

Candidate maturity and repository existence are different dimensions.

A candidate may pass the sovereignty test before a GitHub repository has been created.

Conceptarium therefore records two independent axes.

## Lifecycle state

```text
candidate
    ↓
incubating
    ↓
approved
    ↓
instantiated
    ↓
active
```

Terminal or alternate states:

```text
merged
rejected
dormant
```

### candidate

The idea has enough coherence to deserve a stable Conceptarium identity and examination.

### incubating

The domain is intentionally housed as a province or module inside another Tarium while evidence accumulates.

### approved

The candidate has passed the sovereignty test in principle, but the repository does not yet necessarily exist.

### instantiated

A repository has been created and possesses a minimal local constitution or scaffold.

### active

The repository is a functioning member of the Tarium ecology rather than a merely created shell.

### merged

Investigation concluded that the candidate's deepest ontology belongs inside another Tarium or candidate domain.

Merged is a successful ontological conclusion, not a failure to think.

### rejected

The candidate was examined and found not to justify repository sovereignty.

The record remains because the negative conclusion is knowledge.

### dormant

Work or promotion pressure is intentionally paused without a final sovereignty judgment.

---

# Materialization state

Lifecycle state must not be confused with physical instantiation.

Useful materialization states include:

- `stub` — Conceptarium preserves the candidate definition but no independent repository exists;
- `province` — candidate material is intentionally accumulated inside a host repository/domain;
- `repository` — a separate repository has been created.

This permits the important state:

```text
lifecycle: approved
materialization: stub
```

Meaning:

> **This domain has earned sovereignty in principle, but the repository has not yet been instantiated.**

---

# Candidate stubs

Creating a candidate stub is deliberately cheap.

A stub should preserve enough structure to discipline the impulse without pretending a repository already exists.

A serious stub should normally record:

- working name and aliases;
- canonical object of study;
- core question;
- native entity types;
- native relations;
- major proposed subdomains;
- likely overlaps with existing Tariums;
- why projection into an existing repository may be insufficient;
- example artifacts;
- phenomenological / confessional role where relevant;
- sovereignty-test assessment;
- promotion evidence;
- lifecycle state;
- materialization state.

The governing rule is:

> **Creating the stub is cheap; creating the repository is expensive.**

This gives intellectual excitement somewhere to go without letting excitement itself determine architecture.

---

# Incubation and provinces

A candidate may live for a long time as a province of another repository.

This is desirable when:

- its ontology is still small;
- most of its objects are naturally owned by the host;
- its questions remain primarily a specialization of the host's questions;
- a separate repository would duplicate too much structure;
- the evidence for sovereignty is not yet mature.

Incubation is not second-class status.

It is the constitutional mechanism for **earning secession through accumulated structure**.

## Promotion trigger

A province should be reconsidered for sovereignty when it begins to accumulate:

- native object classes;
- native relation vocabulary;
- specialized methods;
- substantial independent history/genealogy;
- independent tooling or asset needs;
- multiple internal subdomains;
- large bodies of material that strain the host's ontology;
- questions that the host can no longer represent honestly as a mere projection.

At that point the candidate may move:

```text
incubating → approved → instantiated
```

---

# Secession without duplication

When a province becomes sovereign, the goal is not to duplicate every old artifact.

The new Tarium should assume canonical ownership of its deepest ontology.

Other repositories may retain projections and cross-links.

For example:

```text
same cathedral
  ├─ Engineering: load paths and physical systems
  ├─ Architecture: spatial composition
  ├─ Design: design philosophy and critique
  ├─ Habitat: relationship to lived urban space
  └─ Politicarium: political symbolism
```

One object may legitimately receive several projections without several repositories claiming canonical ownership of the same ontology.

---

# Merged and rejected candidates are knowledge

A candidate should not disappear merely because it fails to become a repository.

For example:

> **Typography was considered as an independent domain; investigation showed it was better modeled as a province of Design with projections into Linguarium and Software Studies.**

That conclusion is itself an ontological result.

Conceptarium should therefore preserve candidate history and terminal disposition.

Nothing is wasted merely because sovereignty was denied.

---

# Conceptarium's role

Conceptarium is the constitutional registrar of Tarium candidates, but not the sovereign of active repositories.

It may:

- preserve candidates;
- record lifecycle state;
- evaluate the sovereignty test;
- preserve promotion evidence;
- record merge/rejection reasoning;
- theorize cross-repository boundaries.

Once a repository exists, its local ontology remains sovereign under the Tarium ecology rules.

The lifecycle registry is therefore **pre-sovereignty constitutional state**, not a mechanism for Conceptarium to govern active Tariums.

# Relationship to the Tarium Repository Schema

The [Tarium Repository Schema](./tarium-repository-schema.md) defines the internal epistemic architecture expected of a Tarium once instantiated.

The present document answers a different question:

> **When does a domain deserve an independently instantiated Tarium at all?**

The two constitutions are complementary:

```text
SOVEREIGNTY TEST + LIFECYCLE
    decides whether a repository should exist

TARIUM REPOSITORY SCHEMA
    governs the epistemic layers a repository preserves
```

# Governing synthesis

```text
interesting idea
    ↓
candidate stub
    ↓
incubation / evidence accumulation
    ↓
Tarium Sovereignty Test
    ├─ fails or resolves elsewhere → merged / rejected / dormant
    └─ passes → approved
                  ↓
             instantiated
                  ↓
                active
```

The deepest rule is:

> **Repository sovereignty is earned by ontological independence and structural pressure, not by enthusiasm alone.**
