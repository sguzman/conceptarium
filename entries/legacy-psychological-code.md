# Legacy psychological code

## Definition

**Legacy psychological code** is the collection of old rules still running in the present psyche.

~~~text
earlier environment
        ↓
rule is written
        ↓
rule works well enough
        ↓
environment changes
        ↓
rule keeps executing
~~~

The software metaphor emphasizes persistence without deliberate reauthorization.

## Why "code"?

A psychological rule can:

- trigger automatically;
- branch on conditions;
- suppress actions;
- assign threat;
- allocate attention;
- produce recurring outputs.

The person may experience only the output, not the old rule producing it.

## Legacy does not mean bad

Software can be old and correct.

Likewise psychological code can remain valuable.

The problem is not age.

It is **unreviewed dependence on assumptions that may no longer hold**.

## Relation to archaeology

[Psychological archaeology](./psychological-archaeology.md) discovers where the code came from and what it was designed to solve.

## Relation to stale propositions

Legacy code often contains [Stale propositions](./stale-proposition.md), but it can also contain durable accurate beliefs.

## Relation to refactoring

[Psychological refactoring](./psychological-refactoring.md) modifies the code while preserving useful information and protective functions.

## Failure modes of the metaphor

The psyche is not literally software.

The metaphor becomes misleading if it implies:

- perfect modularity;
- deterministic execution;
- easy deletion;
- one author;
- clean access to source code.

Its purpose is to reason about persistence and revision.
